# iPhone・Windows ミラーリングシステム開発計画書

## 1. プロジェクト概要

### 目的

iPhoneの画面をWindows PCにリアルタイムでミラーリングする独自アプリケーションを開発する。

単なる画面表示ではなく、Windows側で受信した映像フレームを外部の自作アプリケーションから取得し、画像解析に利用できるシステムを構築する。

### 基本方針

- iPhone側はXcode・Swiftで開発する。
- Windows側はC#で開発する。
- 映像通信にはWebRTCを採用する。
- 低遅延・高FPSを重視する。
- 受信映像を画像解析エンジンに直接渡せる設計にする。

## 2. システム構成

### iPhone側

- 開発環境：Xcode

担当機能：

- iPhone画面のキャプチャ
- 映像データの取得
- 映像のエンコード
- Windows PCへの映像送信
- 接続状態の管理
- 配信の開始・停止

使用技術：

- Swift
- ScreenCaptureKit（対応OSの場合）
- ReplayKit（旧OSとの互換性が必要な場合）
- VideoToolbox
- WebRTC

### Windows側

- 開発環境：Visual Studio / Cursor

担当機能：

- iPhoneとの接続
- 映像データの受信
- 映像のデコード
- リアルタイム表示
- 映像フレームの外部提供
- FPS・遅延などの情報表示

使用技術：

- C#
- WPF
- WebRTC
- OpenCV
- Media Foundation（必要に応じて）

## 3. 通信方式

基本的にはWi-Fiを利用する。

iPhoneとWindows PCを同じネットワークに接続し、映像をリアルタイムで転送する。

映像形式：

- H.264
- WebRTC通信

接続方式：

- 初期段階では同一Wi-Fi内での接続
- 将来的には接続先の自動検出を実装

## 4. 目標性能

| 項目 | 初期目標 | 最終目標 |
| --- | --- | --- |
| 解像度 | 1280×720 | 1920×1080 |
| FPS | 30 | 60 |
| 映像遅延 | 200ms以内 | 100ms以内 |
| 映像形式 | H.264 | H.264 |

## 5. Windowsアプリの画面構成

### メイン画面

画面には以下の情報を表示する。

- iPhoneのミラーリング映像
- 接続状態
- 映像解像度
- 現在のFPS
- 映像転送遅延
- 受信状態
- 接続・切断ボタン

### 画像解析との連携

重要な設計要件。

ミラーリング映像を画面に表示する処理と、画像解析に渡す処理を分離する。

映像受信後の処理：

1. 映像フレームを取得
2. 必要に応じて画像形式を変換
3. 解析エンジンにフレームを渡す
4. 解析結果を取得

画面表示の有無にかかわらず、解析エンジンが映像を取得できる構造にする。

これにより、将来的にOpenCVやPythonで開発した独自AIとの連携も可能にする。

## 8. 開発上の注意事項

- iOSの画面キャプチャにはOS側の制約がある。
- 対応するiOSバージョンによって画面取得方式を選定する。
- 映像表示によって画像解析処理が遅くならない設計にする。
- メモリを大量に消費するフレームの蓄積を避ける。
- 解析処理が遅れた場合に古いフレームが蓄積しないようにする。
- 映像の欠落や通信切断から復帰できるようにする。

## 9. 最終的な完成目標

iPhoneをWindows PCに接続するだけで、iPhoneの画面がWindows上にリアルタイム表示される。

さらに、受信した映像を自作アプリケーションから直接取得できる。

最終的には、ミラーリング機能を独立した映像入力システムとして利用し、さまざまな画像解析・AI処理に応用できる構成を目指す。

### 開発の優先順位

1. iPhoneから映像を取得する。
2. Windowsに映像を送る。
3. Windowsに映像を表示する。
4. 映像フレームを外部アプリに渡す。
5. 高速化・安定化する。

まずはミラーリングの基本機能を完成させ、その後に画像解析との連携を進める。
